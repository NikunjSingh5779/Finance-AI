# FinanceAI Mobile Release Checklist

This checklist assumes the mobile client in mobile/ and the existing FastAPI backend are used together.

## A. Local smoke test

1. Pull the latest main branch.

    git pull origin main

2. Verify the backend starts.

    python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

3. Verify the backend from the same PC.

    Invoke-WebRequest http://127.0.0.1:8000/health

4. Find the PC LAN address if testing on a physical phone.

    ipconfig

5. From the phone browser, open:

    http://YOUR-PC-LAN-IP:8000/health

   If this cannot be opened from the phone, fix the Windows firewall/network before testing the app.

6. Install mobile dependencies.

    cd mobile
    npm install
    npx expo install --fix
    npm run typecheck

7. Start Metro.

    npx expo start

8. Open the app and go to Settings. Set the backend URL:
   - Android emulator: http://10.0.2.2:8000
   - Physical Android/iPhone on the same LAN: http://YOUR-PC-LAN-IP:8000
   - iOS Simulator: http://127.0.0.1:8000

9. Test:
   - backend connection
   - account creation/deletion
   - transaction creation/deletion
   - filters/search
   - budgets
   - goals and progress
   - net worth
   - monthly report
   - health/insights
   - expense forecast
   - AI chat
   - pull-to-refresh
   - offline/error states

## B. Create the EAS project

From mobile/:

    npm install --global eas-cli
    eas login
    eas whoami
    eas init
    eas build:configure

Commit any app.json/eas.json changes generated by eas init or eas build:configure.

The repository is already configured for EAS remote developer-facing version management. Do not manually reset Android versionCode or iOS buildNumber after the EAS project is initialized.

## C. Android development APK

    eas build --platform android --profile development

Install the generated APK on a real Android phone or emulator.

For development builds, run:

    npx expo start --dev-client

Then open the FinanceAI development app and keep the backend reachable.

## D. Android preview APK

Use the preview profile for a near-release installable build:

    eas build --platform android --profile preview

Install it on several real Android devices and test the complete app without assuming Expo Go behavior.

## E. Production backend before store build

Do not ship a store binary pointing to localhost or a private LAN address.

Deploy the FastAPI service to a production HTTPS URL. The production service should have:
- HTTPS
- authentication and authorization
- strict per-user data isolation
- hosted persistent database
- secret management
- database backups
- monitoring and error logging
- rate limiting
- privacy and account-deletion flows
- production CORS configuration for the web client if needed

The current backend is a personal single-database service. Public multi-user release is not safe until these backend changes exist.

## F. Production API configuration

Set the public API URL as EXPO_PUBLIC_API_URL for the production build, or configure an equivalent public Expo build variable.

Example:

    EXPO_PUBLIC_API_URL=https://api.example.com

Never put AI provider keys, database passwords, JWT signing secrets, or service-account JSON in EXPO_PUBLIC_* variables.

## G. Production Android build

    eas build --platform android --profile production

This produces an Android App Bundle for store distribution.

## H. Google Play Console

1. Create a Google Play Developer account.
2. Create a new app in Play Console.
3. Use the same Android package ID:

    com.nikunj.financeai.mobile

4. Complete the store listing:
   - app name
   - short description
   - full description
   - category
   - contact email
   - app icon
   - screenshots
   - feature graphic and other required assets
5. Complete App content:
   - privacy policy
   - Data safety
   - content rating
   - target audience
   - ads declaration
   - permissions declarations if any are introduced later
6. Upload the production AAB to Internal testing first.
7. Test on real devices.
8. If your developer account is subject to Google Play's closed-testing requirement for new personal accounts, complete that requirement before requesting production access.
9. Fix every Play Console warning/error.
10. Promote the release to the appropriate testing or production track.
11. For future releases, increment the user-facing version and let EAS remote versioning handle the developer-facing build number.

For EAS Submit instead of manual upload, configure a Google Play service account key in EAS, then:

    eas submit --platform android

## I. iOS production build

    eas build --platform ios --profile production

EAS can build and submit iOS from Windows; an Apple Developer account is still required.

## J. App Store Connect

1. Enroll in the Apple Developer Program.
2. Create the FinanceAI app in App Store Connect.
3. Use the same bundle identifier:

    com.nikunj.financeai.mobile

4. Fill in:
   - app name
   - subtitle
   - description
   - keywords
   - category
   - support URL
   - privacy policy URL
   - screenshots
   - app icon
   - age rating
   - App Privacy answers
5. Upload the iOS production build:

    eas submit --platform ios

6. Wait for App Store Connect processing.
7. Test through TestFlight.
8. Resolve warnings and compliance questions.
9. Select the processed build for the App Store version.
10. Submit the version for App Review.
11. After approval, choose the production release option.

## K. Store-quality assets

Before the production build, add:
- production icon
- Android adaptive icon
- iOS app icon
- splash screen
- Android and iPhone screenshots
- optional promotional graphics
- final app description and keywords

Do not publish with development URLs, placeholder screenshots or placeholder branding.

## L. Production safety checks

Before the public release, verify that:
- no API keys exist in mobile source
- no .env file is committed
- HTTPS is enforced for the public backend
- user data cannot be read by another user
- account deletion actually removes associated data
- backups can be restored
- AI provider credentials remain server-side
- financial data is never logged in plaintext unnecessarily
- test data is not present in the production database
- the privacy policy exactly matches actual data handling
- Play Console Data safety answers match the actual app and SDK behavior
- App Store Connect privacy answers match the actual app and third-party integrations

## M. Versioning for future releases

For a normal JS/UI-only release:

    git pull origin main
    cd mobile
    npm install
    npx expo install --fix
    npm run typecheck
    eas build --platform android --profile production
    eas build --platform ios --profile production

Update the user-facing version in mobile/app.json for a new store release. EAS remote version management is already enabled for developer-facing Android/iOS build versions.

## N. Recommended architecture after launch

Keep this ownership boundary:

    Mobile app
        -> HTTPS REST API
        -> authenticated user context
        -> FinanceAI services
        -> repository layer
        -> production database

The mobile app should remain a client. Business rules and sensitive provider credentials should remain on the server.

## O. Emergency rollback

If a release is broken:
1. Stop promoting the bad release.
2. Use the previous store build where possible.
3. Fix the backend separately if the failure is server-side.
4. Create a new production build with the automatically incremented developer-facing build number.
5. Re-test on internal/closed tracks before promoting again.
